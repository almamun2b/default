# Email Scraper: Code Audit 3

**Date:** 2026-11-07 · **Scope:** all of `src/` (29 files), `scripts/` (12), `test/` (13 suites), CI, `.gitignore` and the docs. Previous audit: 2026-10-13 (all findings fixed; removed from `docs/`, in git history).

## How the audit was done

- Read every source, script, test and doc file end to end.
- `npm run typecheck` clean, `npm test` green (**192 tests**, ~35 s), CI workflow reviewed.
- `npm audit`: **1 high** (a bundle of undici advisories), `npm outdated` checked.
- Probed suspected extraction bugs with throwaway scripts against the real code (underscore/plus/apostrophe/percent local parts, dot-and-at obfuscation, placeholder filters, ROT13, cfemail, JSON-LD, person-name rules).
- Measured the real database (`sites.jsonl` 13,446 rows / 292 MB, `pages.jsonl` 2.23 M lines / 4.5 GB, `run-history.jsonl` 1,327 events) and its largest/average row sizes.
- Cross-checked docs (README flags, ARCHITECTURE, CLAUDE/AGENTS, db-schema) against the code.

**Known trade-offs confirmed deliberate (not bugs):** `example.com|co.nz` placeholders and the `business|company|email|website….(com|co)(.au|nz)` rule do drop real registrable domains such as `business.com.au` and the webmail host `email.com`; `jane.doe`/`john.doe` locals are filtered as placeholders; the browser's DNS rebinding window (Chromium resolves its own connections) remains, as accepted in the previous audit; `ignoreHTTPSErrors: true` in the browser context is a scraper decision.

## Verified working (probed, not just read)

- **Extraction:** underscore (`john_doe@`), plus (`info+jane@`), apostrophe and curly-apostrophe (`o'brien@`), percent locals all pass; uppercase is folded; JSON-LD, microdata, cfemail, mailto, data-attr and text paths all return expected emails and names; `findEmails` gluing rule (`info@acme.co.nzPhone`) intact; name-before-email card logic and `consistentPerson` token matching behave.
- **Regex safety:** every text-scanning regex is literal-anchored with bounded repetition; the `DOT_IN_DOMAIN` loop exits after one unchanged pass.
- **robots.txt:** per-origin rules in both phases, every redirect hop checked before it is requested, Crawl-delay shared by HTTP and browser, 5xx → `robots-unavailable` (retryable), parser-origin quirk handled by `SiteCrawl.allows()`.
- **Safety net:** `netguard` blocklist (incl. NAT64/6to4/TEST-NET), DNS pinning via `connect.lookup`, browser routes on the context (popups, service workers, WebSockets guarded), Chromium sandboxed by default.
- **Concurrency & limits:** per-server slots + adaptive 429/503 backoff + 10 s Crawl-delay cap; queue heap is correct (priority, then FIFO); the `inflight` poll cannot lose pages; abort re-queues the in-flight page attempt.
- **Timeouts:** soft budget → hard limit (+4 min) → 30 s grace → `onPartial` fallback; `untilAborted` cannot produce an unhandled rejection (checked the handler wiring).
- **Persistence:** append-only JSONL with newest-wins; 304 revalidation touches `fetchedAt` in place (13-digit, length-stable); index is derived and self-heals on mismatch; locks are PID files with dead-holder takeover and an exit hook; CSVs are written atomically with formula-safe names; database files and outputs are 0600/0700.
- **Resume/retry:** `leftover`/`resumeState`/`planRetries`/`resumeSite`/`mergeResults` carry unselected parts correctly; capped queues only continue under `--retry-capped`; rate-limited attempts are given back on retry.
- **Repo hygiene:** commits carry no agent attribution; CI installs Chromium and tests Node 22/24; README documents every flag; `docs/db-schema.md` matches the code (record/schema versions 2).

## Method notes and limits

- Suspicions that did **not** hold: underscore locals being dropped (the character class does include `_`), `example.co.nz` handling (deliberate placeholder rule), `waitTurn`/queue lost-wakeup races (checked the worker loop), `untilAborted` rejection leaks, `HashIndex` overflow (`grow()` keeps load below the limit), and `loadList` full-file scans on the fresh-generation path (returns empty without scanning).
- Live probes ran against `src/extract.ts` via `tsx` with throwaway scripts outside the repo; nothing under `results/` was read destructively, written, or re-scraped, and no code was changed in this audit.
